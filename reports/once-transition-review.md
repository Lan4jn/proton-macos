## 一、 问题分级清单 (Issue Classification)

### P0 / 阻断性破坏：无
实验数据客观记录，控制测试与真实 Wine 运行有效捕获了目标控制字 0x20102d440 的状态变迁，核心证据链物理自洽。

### P1 / 关键数据错误与物理路径不一致 (Critical Errors)
1. **时间差数量级重大笔误（单位混淆 1000 倍，324.2 ms 被误写作 324.2 us）**：
   - reports/once-transition.md 第 5.1 节与第 6 节两次宣称：
     > “距离首次映射仅 324.2 微秒，控制字从 0x0 跃迁为 0x1！”
   - **实际时间戳算术独立复核**（逐字取自收据及磁盘 stderr.log）：
     - first_mapped 时间戳：ts_us = 955523381988
     - val_change 时间戳：ts_us = 955523706195
     - **真实绝对差值**：
       Delta_t = 955523706195 - 955523381988 = 324,207 微秒 = 324.207 毫秒 (ms)。
   - **自洽性裁决**：
     - 采样器实际轮询间隔为 usleep(1000)（即 1.0 ms）。如果事件真实间隔只有 324.2 微秒，1 毫秒采样器在绝大多数概率下根本不可能捕获到中间的 0 值；
     - 两个采样事件真实间隔为 324.2 毫秒（跨越了约 324 个采样周期）。因此在 1.0 ms 轮询周期下，该 324.2 毫秒的时间窗口完全充裕且自洽；
     - 执行员将微秒差值（324207 us）除以 1000 得到 324.2 后，荒谬地将单位错标为微秒，导致整整 1000 倍的物理量级谬误。
2. **报告误填 run_dir，且报告记载路径在磁盘上不存在**：
   - 报告正文第 4.3 节声明：run_dir: logs/once-trace/vulkan/run-d19x74b_；
   - **磁盘实测核验**：logs/once-trace/vulkan/run-d19x74b_ 根本不存在（返回 ENOENT）；
   - **收据与物理文件核验**：receipt.json 中记载的真实 run_dir 为 logs/once-trace/vulkan/run-rx848drl。该目录在磁盘真实存在，其 stdout.log 包含完整 Step 3 标记，stderr.log 实际大小为 685,764 字节。
   - **判定**：报告路径系误填，必须以收据与磁盘真实存在的 run-rx848drl 为准。
3. **stderr_bytes 字段第三次发生张冠李戴错填**：
   - 报告正文再次记录：stderr_bytes = 149432；
   - **实际收据核验**：149432 是 Task-70 的历史大小（Task-72 刚因此数值被勘误）；Task-74 真实收据中记载的 stderr_bytes 为 685764 字节，磁盘物理文件 stderr.log 亦严格为 685,764 字节。报告数值失真。

### P2 / 归因边界与过度推论 (Extrapolation & Language Caveats)
1. **“主线程 CAS(0->1)”缺乏直接指令级观测**：
   - 采样器仅以 1.0ms 周期被动读取内存数值，它记录了 val 在某一时刻由 0 变为 1，但从未直接观测到 CAS 汇编指令（如 casa / stxr）的执行瞬间，亦未捕获写入当时的指令级 PC；
   - 将该 0->1 写入归因于“主线程 CAS(0->1)”是基于 glibc pthread_once 汇编行为的反推与合理推测，属于强语义推断，不能声称具备指令级物理观测支撑。
2. **“递归重入”仍为推论，“确凿证实”措辞严重不当**：
   - 采样器证实了内存字在 vkCreateInstance 早期（324.2ms 内）由 0 变为 1；随后在数秒后的第 855 号系统调用处，主线程因该字为 1 陷入 Futex 等待；
   - **关键证据链断层**：观测器从未捕获到主线程到底是在哪一行代码、哪一个调用栈将该控制字置为 1，也未捕获外层调用者的上下文；
   - **竞争分支依然存活**：
     - 推论分支 1（同线程递归自锁）：同一线程外层调用了一次 pthread_once，在未完成时深层又调了一次同一控制字；
     - 推论分支 2（异常泄漏/未配对退出）：初始化例程在置 1 后因某些非致命返回/长跳转（longjmp）未能执行到置 2 及 wake，导致该全局单例永久处于脏状态 1，后续正常调用到达时被误锁；
   - 报告直接使用“确凿证实递归自锁死锁”属于过度推论，极不严谨。在未抓取到两次调用栈之前，必须统一定性为“强证据排他性推测”。

## 三、 全部 26 条 ONCE_TRANSITION 原始记录与时序剖析

收据中提取的 26 条记录按进程与时序分类呈现如下：

### 3.1 辅助/中间子进程生命周期（共 23 条）
在主 Wine 进程启动前及并发期间，多个子进程/辅助工具（PID 98964..99042）在其生命周期内初次映射或销毁了该地址区段，部分加载只读段时的瞬态值被记录，但均伴随子进程退出：
- pid=98967: first_mapped (0xa9037bfd)
- pid=99002: first_mapped -> val_change (0x0)
- pid=99006: first_mapped (0xd65f03c0)
- 其余均为未映射初读或常规分配，与末端挂起进程无关。

### 3.2 主 Wine 进程（PID 98953）核心三事件（逐字提取）
在执行测试的主 Wine 进程中，采样器精确捕获到 3 个且仅有 3 个状态事件：

1. **未映射期探测（first_read）**：
   `ONCE_TRANSITION ts_us=955474027498 pid=98953 gtid=-1 uaddr=0x20102d440 val=0x0 (dec:0) prev_val=0x0 mapped=0 range=[0x0,0x0) prot=--- reason=first_read elr=0xfd0001c81c lr=0xfd0000a5f0 trigger=poll_1ms`
2. **段建立首读（first_mapped）**：
   `ONCE_TRANSITION ts_us=955523381988 pid=98953 gtid=-1 uaddr=0x20102d440 val=0x0 (dec:0) prev_val=0x0 mapped=1 range=[0x200ffe000,0x20106e000) prot=rw- reason=first_mapped elr=0x10040580 lr=0x100291cc trigger=poll_1ms`
   - *证据定性*：在匿名私有段建立的第 1 次采样中，该地址严格为 0x0。彻底排除了“首次可见即非 0 / 堆复用污染”的假设 A2。
3. **单向跃迁写 1（val_change）**：
   `ONCE_TRANSITION ts_us=955523706195 pid=98953 gtid=-1 uaddr=0x20102d440 val=0x1 (dec:1) prev_val=0x0 mapped=1 range=[0x200ffe000,0x20106e000) prot=rw- reason=val_change elr=0x10040580 lr=0x100291cc trigger=poll_1ms`
   - 时间戳计算：955523706195 - 955523381988 = 324207 us = 324.207 ms。
   - 采样器报告的寄存器快照为用户态 Vulkan 加载器代码：elr=0x10040580, lr=0x100291cc。

## 四、 采样器设计、盲区与时序真实开销评估

从 sources/elfuse-once-trace-derived/src/syscall/syscall.c 源码第 2656–2750 行对采样器进行逆向审计：

1. **真实采样周期**：
   - 采样线程执行 usleep(1000)，理论轮询间隔为 1.0 ms；
   - 实际调用点还挂接在 lifecycle_sc_entry 与 lifecycle_sc_return 上。但经检查，PID 98953 的两条关键 transition 行的 trigger 字段显式记录为 trigger=poll_1ms，证明它们确系由独立的 1ms 轮询线程捕获。
2. **时间戳来源**：
   - 时间戳直接取自采样发生瞬间宿主调用的 clock_gettime(CLOCK_MONOTONIC, &ts)（第 2693 行）；
   - **不可支持推论**：采样时间戳代表宿主发现并读取该值的时刻，而不是 guest CPU 内部执行硬件写入指令的真实时刻。真实的物理写 1 发生在此次采样之前的某一个微秒。因此，执行员声称“相隔 324.2 微秒发生写入”在物理原理上亦不可成立。
3. **采样机制的理论盲区**：
   - **两次采样间的“写-改-回”盲区**：若有代码在两个 1ms 采样脉冲之间极速将 0 改为 2 再改回 1，采样器无法感知中间跳变（但根据 glibc pthread_once 状态机，状态只能单向推进 0->1->2，不存在回滚）；
   - **早期短暂映射盲区**：如果该内存段在建立后曾经发生过 unmap 并重新 map，且中间相隔时间小于 1ms，可能会丢失段重构记录（但本案中映射基址与大小始终严格为 [0x200ffe000,0x20106e000)，未见重新分配）。

## 五、 独立复核核心结论

1. **关于时间差的勘误裁决**：
   - 否定报告中的“相隔 324.2 微秒”表述；
   - **确立真实物理时间差为 324.2 毫秒**（324207 us）。这一跨度与 1.0ms 采样周期完全自洽。
2. **关于假设 A2 的裁决**：
   - **确凿排除假设 A2**：内存映射建立时首读确凿为 0x0，排除了加载期污染或未清零残留。
3. **关于假设 A 的裁决**：
   - **维持强证据候选推论，撤销“确凿证实”定性**：
     - 已证实事实：主进程单线程存活、初值为 0、随后变为 1、末端唯一 futex 因值为 1 挂起；
     - 未证推论：将上述事实串联为“同一函数递归重入”属于合理的排他性推论，但由于缺乏两次调用的完整用户态调用栈，不得宣称“确凿证实”。
