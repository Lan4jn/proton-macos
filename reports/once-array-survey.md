## 二、 word == 1 控制字阵列排序与间距分析

### 1. 处于 word == 1 的控制字清单（按物理地址升序排列）
在全量统计中，主 Wine 进程内最终处于 `word == 1`（`ONCE_IN_PROGRESS`，即正在初始化但未完成）的地址严格只有 **2 个**：

| 物理地址 | 相对 448KiB 段偏移 | 与前一地址间距 (Bytes) | 差值十六进制 | 是否为 0x38 的倍数 | 倍数因子 | 最终状态 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **`0x20102d440`** | `0x2f440` (193,600) | 基准 (0) | `0x0` | 是 | 0 * 0x38 | `word=1` (死锁点 1) |
| **`0x20102d478`** | `0x2f478` (193,656) | **56 字节** | **`0x38`** | **是** | **1 * 0x38** | `word=1` (死锁点 2) |

### 2. 数学特征与几何分布判定
- **精准 56 字节对齐**：两控制字地址严格满足：
  `Delta = 0x20102d478 - 0x20102d440 = 0x38 = 56 Bytes = 1 * 0x38`
- **其他地址的间距检验**：
  - `0x20102d440 - 0x20100de08 = 0x1f638 = 128,568 Bytes`，无法被 56 整除 (128568 / 56 ≈ 2295.86)；
  - `0x20102d440 - 0x200ffdd10 = 0x2f730 = 194,352 Bytes`，无法被 56 整除 (194352 / 56 ≈ 3470.57)；
- **结论**：在 448 KiB 匿名私有段中，存在一个**以 56 字节（0x38）为固定步长的局部连续结构体或结构体数组**，`0x20102d440` 与 `0x20102d478` 正是该结构中相邻槽位的两个 `pthread_once_t` 控制字。

## 三、 word == 1 控制字的时序演化模式（“CAS 设 1 后长期停滞”）

对这 2 个 `word == 1` 地址的时序轨迹进行对比，证实它们具有完全相同的状态机滞留模式：

```text
[时间轴时序图 (Monotonic Timeline)]

ts = 977897241236 (t0)      ===> 【首次进入 0x20102d440】: word=0, LR=0x200f39d24
                                 执行原子 CAS 0 -> 1，进入外层初始化例程

ts = 977900171408 (t0+2.93s) ===> 【首次进入 0x20102d478】: word=0, LR=0x200f3af04
                                 外层初始化例程调用子系统初始化，执行原子 CAS 0 -> 1

ts = 977906698324 (t0+9.45s) ===> 【二次进入 0x20102d440】: word=1, LR=0x200f3a3f8
                                 嵌套重入外层 once，因 word==1 陷入 futex wait (死锁 1)

[常规 Baseline 运行分支]     ===> 线程死锁在 0x20102d440，0x20102d478 永远得不到恢复机会，两者全部停在 1

[Bypass 诊断放行分支]        ===> 0x20102d440 被强制置 2 并返回 0
ts = 978694414140 (+45us)    ===> 线程继续执行，立即进入 0x20102d478 的 futex wait (死锁 2)！
                                 证实 0x20102d478 在经历数百毫秒后同样保持在 word==1！
```

**共同模式确立**：
1. **两阶段进入**：两控制字均经历了“初次进入 CAS 0->1 -> 因级联调用停滞未完成置 2 -> 后续再次触碰触发 futex wait”；
2. **非初值污染**：两者在首次被触及之前，初始读取严格均为 `0x00`（彻底排除堆残留或内存脏字假说）；
3. **因果依存链**：外层 `0x20102d440` 的卡死直接导致内层 `0x20102d478` 失去了完成初始化的机会，形成了级联停滞。

## 五、 观测事实 vs 结构假设的界限与反驳条件

为保证科学严谨性，严格区隔直接证据与模型推测：

### 1. 坚实的观测事实 (Direct Empirical Facts)
1. 在 Wine 主进程中，全生命周期共调用 19 次 `pthread_once`，涉及 5 个不同控制字；
2. 最终处于 `word == 1` 的控制字严格只有 2 个：`0x20102d440` 与 `0x20102d478`；
3. 两者的物理间距严格为 56 字节（`0x38`）；
4. 两者在 baseline 与 bypass 下分别成为前序与后序的系统调用挂起点。

### 2. 结构模型假设 (Structural Hypotheses)
- **假设 A（结构体成员槽位假说）**：`0x20102d440` 与 `0x20102d478` 是 Khronos Vulkan Loader 内部某个单一单例对象（例如 `struct loader_instance`）的两个字段成员，该对象每个子阶段大小或槽位间距为 56 字节；
- **假设 B（组件数组假说）**：该内存段是一个驱动扩展模块的数组 `struct vulkan_module modules[]`，每个模块拥有独立的 `pthread_once_t once;` 字段位于结构体头部，结构体大小 `sizeof(module) == 56`。

### 3. 可反驳条件 (Falsification Criteria)
- **条件 1（间距反驳）**：若在后续实验中放行 `0x20102d478` 后，出现的第 3 个死锁点与 `0x20102d440` 的差值**不是 0x38 的整数倍**，则“固定 56 字节连续数组假设”即被推翻，转为“离散成员假说”；
- **条件 2（模块归属反驳）**：若逆向分析证实 `0x200f39d24` 与 `0x200f3af04` 来自完全不相干的两个不同 C 文件编译单元，则“单一结构体成员假说”即被推翻；
- **条件 3（独立完成反驳）**：若某次实验在解除外层锁定后，次级控制字自行置 2 返回，则“级联未置 2”假设被推翻。

## 六、 0x70000 匿名段边界核验

- **448 KiB 匿名段范围**：`[0x200ffe000, 0x20106e000)`
- **核验结论**：
  - `0x20102d440` 位于偏移 `0x2f440`，在段内；
  - `0x20102d478` 位于偏移 `0x2f478`，在段内；
  - `0x20100de08` 位于偏移 `0xfe08`，在段内（但 `word=0`）；
  - **在全量日志中，不存在任何超出 0x70000 段范围且处于 `word == 1` 的控制字地址**。
  - 段外出现的唯一其他 once 地址为 `0x20d6a15dc`（位于驱动段），其实测终态为 `word == 2`（成功完成），未发生停滞。

## 七、 总结与落盘索引

本调研证实：“一组 once 全部停在 1”在物理上收敛为 **位于 448 KiB 匿名私有段中、相距恰好 56 字节（0x38）的一对连续控制字（`0x20102d440` 与 `0x20102d478`）**。它们是由外层初始化调用内层初始化所形成的嵌套级联停滞，确凿构成了连续链条。
